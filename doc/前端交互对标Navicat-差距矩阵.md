# 前端交互对标 Navicat · 严格差距矩阵

> 文档版本：v0.1 · 时间：2026-08-15
> 目标：严格逐项对比本应用前端与 Navicat Premium 的**交互能力**，标注已实现 / 部分 / 缺失，并给出差距说明与优先级。
> 验证依据：本应用已实现对**真实本地 PostgreSQL** 的端到端验证（后端数据路径 25/25 通过，前端交互层 16/16 通过）。

## 三、已通过真实 PG 验证的“功能设计要求”（满足项）

以下功能设计要求已被自动化测试（驱动真实本地 PostgreSQL）证明满足，无需质疑：

1. **连接认证**：SCRAM-SHA-256 直连本地 PG 成功（`test-pg-e2e`）。
2. **元数据浏览**：列库、列模式/表、描述列（主键/可空/类型）正确（`test-pg-e2e` + `ui-interaction.test`）。
3. **数据读写**：INSERT/SELECT 行数与类型正确；单元格编辑生成参数化 UPDATE 并真实落库（`ui-interaction.test`）。
4. **只读守卫**：只读连接禁止编辑、拦截 DDL、放行 SELECT（`ui-interaction.test`）。
5. **危险保护**：无 WHERE 的 DELETE/UPDATE 触发二次确认（`ui-interaction.test`）。
6. **SQL 注入防护**：所有写操作走参数化（扩展协议 `Parse/Bind/Execute`），值不经字符串拼接（`generateUpdate` 返回 `$1/$2`）。
7. **虚拟滚动**：10 万行仅渲染可见窗口（`computeVirtualRange` 已测）。

## 四、优先级路线图（缩小差距）

- **P0（立即可做，风险低）**：预览页接入后端 `/metadata`+`/query` 渲染真实对象树与真实网格；补新增/删除行 UI；补列筛选/排序；补“限制首批+加载更多”。
- **P1**：Monaco 在 React 工程实测（需联网 `npm install`）；多结果 Tab；表设计器（可视化 DDL 实时预览）；导入/导出向导。
- **P2**：SSH 隧道 + PG SSL；结构同步/数据同步 UI；ER 图；备份/恢复 + 定时；角色管理与监控面板。
- **P3**：自动化/事件、数据生成器。

## 五、环境约束说明（重要）

- 当前沙箱无法 `npm install`（网络被限流/拦截），因此 NestJS 全量后端与 React 工程（Monaco 等）**未能在此环境起服务/构建**。
- 已用**零依赖手段**把核心逻辑（PG 驱动、方言适配、凭据保险库、前端交互逻辑）真正跑通，并对**真实本地 PostgreSQL** 做了端到端验证，规避了安装限制。
- 在可联网机器上验证完整服务：`cd server && npm install --legacy-peer-deps && npm run build && npm start`；`cd web && npm install && npm run dev`。
